# ADR-0003 — SAF user-picked folder as filesystem root

## Status
Accepted

## Context
ADR-0001 declares the filesystem as the source of truth. On Android the choice
of storage location has strong consequences for sync, backup, and user data
ownership.

Options considered:
1. App-internal storage (`filesDir`) — private, invisible, uninstall-safe only via cloud backup.
2. App-scoped external (`getExternalFilesDir`) — visible over USB, wiped on uninstall.
3. User-picked folder via Storage Access Framework (`ACTION_OPEN_DOCUMENT_TREE`).

## Decision
Use option 3. On first launch the user picks (or creates) a folder — suggested
default: `Documents/ThoughtCanvas/`. The persistable URI permission is stored
in DataStore. All read/write operations go through a `FileRepository`
abstraction backed by `DocumentFile`.

## Consequences
- Cloud sync becomes an out-of-app concern: Syncthing, Nextcloud, rclone, or
  git via Termux can operate on the folder without any code inside
  ThoughtCanvas managing conflicts.
- Uninstall does not delete user data.
- `DocumentFile` I/O is slower than `java.io.File`; caching and batched writes
  will be added when performance matters.
- Any future in-app sync provider must respect the same folder layout.
